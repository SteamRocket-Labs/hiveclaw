# Hive 前端设计需求说明

> 状态：v0.4，设计师原型输入文档
>
> 日期：2026-06-07
>
> 用途：向设计师说明 Hive 的核心功能点和业务流程，用于整套前端页面、UI 和交互原型设计。

---

## 1. 产品定义

Hive 是企业内部的 AI 数字员工平台。

员工可以在 Hive 中创建、配置、使用自己的 AI 数字员工；管理层可以在 Hive 中管理公司 workspace、成员、权限、能力、预算、审批、审计和公司级数字员工资产。

核心对象：

| 对象 | 含义 |
|---|---|
| 员工 | 使用平台的公司成员。 |
| 管理层 | 管理 workspace、成员、权限和公司级能力的人。 |
| Workspace | 一个公司的工作空间。 |
| Group / 部门 / 团队 | Workspace 内的组织分组，用于成员归属、权限和能力范围。 |
| 数字员工 | 员工或公司创建的 AI 工作伙伴。 |
| 公司控制中台 | 管理层治理整个 workspace 的后台。 |

---

## 2. 用户角色

### 2.1 员工

员工可以：

- 注册和登录平台。
- 加入 workspace。
- 查看自己所属的 workspace 和 group。
- 查看可用的数字员工。
- 创建自己的数字员工。
- 配置自己有管理权限的数字员工。
- 与数字员工对话并交办任务。
- 查看任务计划、进度、结果和产物。
- 确认、修改或拒绝需要人工确认的计划和动作。
- 将成功任务保存为流程、模板或候选资产。

### 2.2 管理层

管理层可以：

- 创建或管理 workspace。
- 邀请员工加入 workspace。
- 管理成员、group、部门、角色和配额。
- 查看和管理 workspace 内的数字员工。
- 管理公司级模型、预算、渠道、工具、技能和审批规则。
- 管理公司级记忆、知识、流程模板、专家角色和资产库。
- 查看待审批事项。
- 查看审计记录、风险和异常。
- 决定哪些能力开放给哪些员工、group 或数字员工。

## 3. 功能点清单

### 3.1 账号与 workspace

需要支持：

- 注册账号。
- 登录账号。
- 注册后无 workspace 时进入 workspace setup。
- 输入邀请码加入已有 workspace。
- 创建新的 workspace。
- 查看当前所属 workspace。
- 切换 workspace（如用户有多个 workspace 权限）。

### 3.2 成员与 group

需要支持：

- 查看 workspace 成员。
- 邀请员工加入 workspace。
- 生成和管理邀请码。
- 管理 group、部门或团队。
- 将员工分配到 group。
- 查看员工所属 group。
- 根据 group 控制数字员工和能力的可见范围。

### 3.3 数字员工列表

需要支持：

- 查看自己可用的数字员工。
- 查看自己创建的数字员工。
- 查看公司推荐或公司标准数字员工。
- 搜索数字员工。
- 按状态、职责、能力、归属范围筛选数字员工。
- 创建新数字员工。

每个数字员工需要展示：

- 名称。
- 头像。
- 职责。
- 当前状态。
- 可见范围。
- 所属创建者或负责人。
- 可用能力摘要。
- 最近工作状态。
- 是否有异常或待确认事项。

### 3.4 创建数字员工

需要支持三种创建方式：

1. 从空白创建。
2. 从公司模板创建。
3. 通过自然语言助手创建。

创建流程需要覆盖：

- 输入名称。
- 描述职责。
- 设置头像或形象。
- 设置工作说明。
- 设置可见范围。
- 选择基础能力。
- 选择技能。
- 选择专家角色。
- 选择可协作的其他数字员工。
- 确认哪些能力由公司管理。
- 创建完成后进入数字员工工作台。

### 3.5 数字员工详情 / 工作台

数字员工工作台需要包含：

- 数字员工身份信息。
- 当前状态。
- 对话与任务入口。
- 正在进行的任务。
- 任务计划。
- 工作进度。
- 产物。
- 能力配置。
- 记忆与知识。
- A2A 协作关系。
- 自动化和工作流。
- 权限与分享。
- 审批和风险信息。
- 设置。

### 3.6 数字员工权限与分享

需要支持：

- 设置谁可以使用数字员工。
- 设置谁可以管理数字员工。
- 设置仅自己可见。
- 设置指定员工可见。
- 设置指定 group 可见。
- 设置全公司可见。
- 展示当前用户对数字员工的权限：可使用、可管理、只读、无权限。
- 权限不足时提供申请或联系管理员入口。

权限层级：

| 权限 | 含义 |
|---|---|
| 使用权限 | 可以对话、交办任务、查看自己有权限的结果。 |
| 管理权限 | 可以修改数字员工配置、能力、可见范围。 |
| 公司治理权限 | 可以配置公司级能力、渠道、预算、审批和规则。 |

### 3.7 数字员工能力配置

需要支持以下能力类型：

| 能力类型 | 用户看到的含义 |
|---|---|
| 对话与任务 | 数字员工可以接收任务并输出结果。 |
| 文件与产物 | 数字员工可以读取资料、生成文档和保存结果。 |
| 记忆与知识 | 数字员工可以记住偏好、经验和公司知识。 |
| 工具 | 数字员工可以使用公司开放的工具。 |
| 技能 | 数字员工可以启用特定工作技能。 |
| 专家角色 | 数字员工可以调用内部专家分工。 |
| 工作流 | 数字员工可以执行稳定流程。 |
| 渠道 | 数字员工可以在飞书、Slack、微信、邮件等渠道工作。 |
| 审批 | 高风险动作会请求人工确认。 |
| A2A 协作 | 数字员工可以与其他数字员工协作。 |

每个能力需要展示状态：

- 可用。
- 已启用。
- 需要管理员配置。
- 需要审批。
- 公司未开放。
- 仅管理员可改。
- 最近失败。

### 3.8 对话与任务执行

需要支持：

- 创建会话。
- 查看历史会话。
- 发送消息。
- 上传文件和资料。
- 查看数字员工回复。
- 查看数字员工是否正在工作。
- 查看执行过程。
- 查看任务计划。
- 查看工作进度。
- 查看 A2A 委派过程。
- 查看结果和产物。
- 继续追问。
- 修改任务方向。
- 取消或停止任务。
- 将结果保存为流程或模板。

### 3.9 计划确认

当任务需要人工确认时，需要展示计划确认界面。

计划确认需要展示：

- 任务目标。
- 执行步骤。
- 假设。
- 需要用户确认的问题。
- 风险。
- 影响范围。
- 会使用的能力或渠道。
- 预期产物。
- 确认、修改、拒绝、继续执行。

### 3.10 工作进度与产物

需要展示：

- 当前正在做什么。
- 已完成步骤。
- 待完成步骤。
- 卡住的问题。
- 中间发现。
- 失败尝试。
- 验证结果。
- 产物列表。
- 文档、报告、文件、导出结果。
- 继续修改或导出入口。

### 3.11 A2A 协作

A2A 是数字员工之间的协作。

需要支持三类展示：

| 类型 | 含义 |
|---|---|
| 协作关系 | 某个数字员工可以与哪些数字员工协作。 |
| 任务委派 | 一个数字员工把任务的一部分交给另一个数字员工。 |
| 专家角色 | 某个数字员工内部的专业分工。 |

需要展示：

- 协作对象。
- 协作对象职责。
- 协作关系类型。
- 任务委派记录。
- 委派目标。
- 被委派数字员工的执行状态。
- 返回结果。
- 权限不足或需要审批的状态。
- 管理层查看公司内 A2A 协作网络和风险。

### 3.12 自动化与工作流

需要支持：

- 将一次任务保存为可复用流程。
- 查看流程模板。
- 创建定时任务。
- 创建触发规则。
- 查看流程运行记录。
- 查看运行状态：运行中、暂停、等待审批、失败、完成。
- 从成功任务中推荐保存为流程。
- 管理层审核和发布公司标准流程。

### 3.13 记忆与知识

需要支持：

- 查看数字员工记住了什么。
- 查看公司共享知识。
- 查看当前任务使用了哪些记忆或知识。
- 编辑、删除或禁用有权限的记忆。
- 展示敏感信息或权限限制。
- 展示记忆来源。
- 管理层管理公司级记忆规则和共享知识。

### 3.14 文档与研究

需要支持：

- 查看 AI 生成的文档。
- 查看研究报告。
- 查看资料来源。
- 编辑文档。
- 导出文档。
- 继续研究或修订。
- 将文档、报告与任务、对话、流程关联。

### 3.15 审批中心

需要支持：

- 查看待审批事项。
- 查看发起人。
- 查看相关数字员工。
- 查看动作说明。
- 查看风险和影响范围。
- 查看上下文。
- 批准。
- 拒绝。
- 要求修改。
- 查看审批历史。

### 3.16 公司控制中台

管理层需要一个公司级后台入口。

需要包含：

- 公司总览。
- 成员与组织。
- 数字员工治理。
- 模型与预算。
- 能力与工具。
- 记忆治理。
- 渠道连接。
- 审批中心。
- 审计记录。
- 自动化与资产库。

### 3.17 公司资产库

需要支持：

- 公司标准数字员工模板。
- 公司标准技能。
- 公司专家角色。
- 公司工作流模板。
- 员工提交的候选资产。
- 候选资产审核。
- 资产来源说明。
- 资产适用范围。
- 资产版本。
- 启用、停用、更新。

## 4. 业务流程

### 4.1 员工注册并加入 workspace

```text
打开平台
  -> 注册账号或登录
  -> 判断是否已有 workspace
  -> 没有 workspace 时进入 setup
  -> 输入邀请码加入已有 workspace
  -> 或创建新的 workspace
  -> 进入员工首页
```

### 4.2 管理层创建 workspace

```text
注册账号
  -> 创建 workspace
  -> 成为该 workspace 的管理员
  -> 配置公司信息
  -> 配置模型和预算
  -> 邀请员工
  -> 配置 group / 部门
  -> 创建或配置第一个数字员工
  -> 进入公司控制中台
```

### 4.3 管理层邀请员工

```text
进入公司控制中台
  -> 进入成员与组织
  -> 生成邀请码
  -> 设置邀请码使用次数
  -> 将邀请码发送给员工
  -> 员工注册账号
  -> 员工输入邀请码加入 workspace
  -> 管理层为员工分配 group / 角色 / 权限
```

### 4.4 员工创建数字员工

```text
进入员工首页
  -> 点击创建数字员工
  -> 选择创建方式：空白 / 模板 / 自然语言助手
  -> 填写名称和职责
  -> 设置可见范围
  -> 选择基础能力
  -> 选择技能和专家角色
  -> 设置 A2A 协作对象
  -> 查看公司限制和需要审批的能力
  -> 确认创建
  -> 进入数字员工工作台
```

### 4.5 员工配置数字员工能力

```text
进入数字员工工作台
  -> 进入能力配置
  -> 查看可用能力
  -> 启用员工可配置的能力
  -> 对需要管理员的能力发起申请或查看提示
  -> 保存配置
  -> 返回工作台
```

### 4.6 员工设置权限与分享

```text
进入数字员工工作台
  -> 进入权限与分享
  -> 选择可见范围：仅自己 / 指定员工 / 指定 group / 全公司
  -> 设置使用权限
  -> 设置管理权限
  -> 保存
  -> 被授权员工可以看到或使用该数字员工
```

### 4.7 员工交办任务

```text
进入数字员工工作台
  -> 打开对话
  -> 输入任务
  -> 上传资料
  -> 数字员工判断是否需要计划确认
  -> 如果需要，展示计划确认
  -> 员工确认或修改计划
  -> 数字员工开始执行
  -> 页面展示进度、A2A 协作和中间产物
  -> 生成最终结果
  -> 员工审阅结果
  -> 继续修改 / 导出 / 保存为流程
```

### 4.8 任务中的 A2A 协作

```text
员工向主数字员工交办任务
  -> 主数字员工判断需要其他数字员工协作
  -> 展示协作对象和委派目标
  -> 被委派数字员工开始执行子任务
  -> 页面展示子任务进度
  -> 被委派数字员工返回结果
  -> 主数字员工整合结果
  -> 员工看到最终结果和协作过程
```

### 4.9 需要审批的动作

```text
数字员工准备执行高风险或受限动作
  -> 生成审批请求
  -> 员工或管理层收到待审批事项
  -> 查看动作说明、风险、影响范围和上下文
  -> 批准 / 拒绝 / 要求修改
  -> 数字员工根据审批结果继续或停止
  -> 审批记录进入审计
```

### 4.10 成功任务保存为流程

```text
任务完成
  -> 员工选择保存为流程或模板
  -> 系统生成候选流程
  -> 员工确认名称、适用场景和步骤
  -> 保存为个人流程
  -> 如适合公司复用，提交为候选资产
  -> 管理层审核
  -> 通过后进入公司资产库
  -> 其他员工或数字员工可以复用
```

### 4.11 管理层治理数字员工

```text
进入公司控制中台
  -> 查看数字员工总览
  -> 查看每个数字员工的负责人、状态、能力和风险
  -> 调整可见范围或管理员
  -> 停用异常数字员工
  -> 查看工作记录和审计
  -> 处理待审批事项
```

### 4.12 管理层配置公司能力

```text
进入公司控制中台
  -> 进入能力与工具
  -> 配置公司模型、工具、渠道和技能
  -> 设置哪些能力开放给哪些 group 或数字员工
  -> 设置哪些能力需要审批
  -> 保存配置
  -> 员工在数字员工能力配置中看到可用范围
```

### 4.13 管理层管理公司资产库

```text
进入公司控制中台
  -> 进入公司资产库
  -> 查看标准模板、技能、专家角色、流程
  -> 查看员工提交的候选资产
  -> 查看来源、适用范围和使用记录
  -> 审核通过或拒绝
  -> 发布为公司标准资产
  -> 指定可用范围
  -> 员工和数字员工复用
```
